# UX-08 — Replace competing production lists with one work queue

**Status:** In progress · **Priority:** P0  
**Feature:** [Consistent interface and editorial experience](../features/ui-ux-consistency.md)  
**Dependencies:** [UX-01](UX-01.md), [UX-04](UX-04.md), [UX-05](UX-05.md), [UX-07](UX-07.md)

As an editor, I want one clear list of the work in production, so I can resume the right stage without comparing duplicate queues.

## Current evidence

Production renders a DailyEditorialPlannerPanel, a selected-Story card queue, and EditorialEvaluationPanel's selected table on the same view. The queue reports content availability but not the exact script or image review blocker.

**Surfaces:** [radar-dashboard.tsx](../../src/app/radar-dashboard.tsx) · [daily-editorial-planner-panel.tsx](../../src/app/daily-editorial-planner-panel.tsx) · [topic-overview-panel.tsx](../../src/app/topic-overview-panel.tsx).

## Acceptance criteria

1. Choose one primary Production queue. Recommendations remain accessible in their daily/discovery context; duplicate tables do not compete with the work list.
2. Each item shows Story, editorial line when known, current saved revision, factual workflow state, blocker, and the next supported action.
3. Provide In preparation, Needs review, and Ready views backed by actual state. Use the existing OVW-04 aggregate where available; do not infer approval from the presence of an image.
4. Open the relevant Content, Focus, Script, Visuals, or Publication tab from the item and restore filters and position on return.
5. Count Stories consistently and distinguish an active version from historical versions. A publication on one destination does not erase pending work on another.
6. Support list loading, empty, recoverable error, missing artifact, and stale revision with the shared component patterns.

## Validation

Render selected-only, draft-needs-review, stale-images, ready, and partly-published Stories. Confirm one primary entry per Story and that each next action opens the correct saved version.

## Scope and delivery

Coordinate with OVW-04 rather than creating a parallel workflow-state model. Backend queue data that does not exist is an explicit prerequisite.

## Implementation progress — September 28, 2026

- The daily recommendation planner has been removed from Production and placed in Today, reducing competing production surfaces.
- The selected-story evaluation table is now an accessible Advanced review disclosure beneath the Production cards. The primary Production view has one visible queue, while filters and bulk actions remain available on demand.
- Discover provides a persistent Selected shortcut to this queue. Queue cards show the known editorial line, source, and content availability, with a direct draft-workspace action.
- Remaining: replace the current card queue with one backed by OVW-04’s exact workflow state and blockers, then validate version-aware navigation and recovery.
