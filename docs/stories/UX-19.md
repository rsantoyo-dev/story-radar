# UX-19 — Guide channel connection and explain publishing readiness

**Status:** In progress · **Priority:** P1  
**Feature:** [Consistent interface and editorial experience](../features/ui-ux-consistency.md)  
**Dependencies:** [UX-01](UX-01.md), [UX-02](UX-02.md), [UX-03](UX-03.md), [UX-04](UX-04.md), [UX-05](UX-05.md)

As an editor, I want to see which account is connected and what capability is missing, so I can fix a connection without understanding app internals.

## Current evidence

Connection, health problems, verification, sync, publishing access, and custom-app credentials are grouped using brand-profile surfaces. Connection status and the separate publishing-access check expose different states, but there is no unified next-action summary.

**Surfaces:** [meta-connection-panel.tsx](../../src/app/meta-connection-panel.tsx) · [instagram-publishing-access-panel.tsx](../../src/app/instagram-publishing-access-panel.tsx).

## Acceptance criteria

1. Use a channel card with platform, exact account, connection state, and one next action. Keep Connected, Can publish, Can sync, and Metrics available as separate capabilities.
2. Guide disconnected, expired, insufficient-permission, publishing-unverified, and operational cases with concise steps. Link back to the blocked publication when connection was opened from there.
3. Keep environment and app credentials in an advanced administrative section. Show sensitive values only through existing authorized flows and do not expose tokens to previews or client logs.
4. Make disconnect or account replacement consequences explicit, preserve delivery/history references, and retain current server suspension and revision rules.
5. Preserve direct Instagram Login. Add Connect Meta and asset selection only through PUB-09 and the AUTH prerequisites, using the same visual patterns.
6. Use the common feedback and disabled-reason components for verify, reconnect, and sync without blocking unrelated editorial work.

## Validation

Exercise disconnected, partial-permission, expired, healthy-but-not-verified, and missing-metrics fixtures. Change the destination account and confirm an existing authorized package is not silently redirected.

## Scope and delivery

Related: PUB-02/09 and AUTH-03–06. A visual readiness indicator never replaces server permission checks.

## Implementation progress — September 28, 2026

- The Instagram connection panel separates connected, publishing, sync, and insights states. Errors and blockers use persistent notices; disconnect confirmation explains that history remains while future work stops.
- Remaining: capability-specific recovery paths, account replacement consequences, permission fixtures, and alignment with future Meta/AUTH work.

Apply the feature's [shared visual contract and definition of done](../features/ui-ux-consistency.md), including UXDSL, English UI copy, responsive/keyboard checks, and preservation of approvals and history. Record implementation and visual evidence before changing status. The [component audit](../ui-ux-component-audit.md) lists every affected consumer.
