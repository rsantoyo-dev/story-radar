# UX-04 — Unify statuses, feedback, and English action language

**Status:** In progress · **Priority:** P0  
**Feature:** [Consistent interface and editorial experience](../features/ui-ux-consistency.md)  
**Dependencies:** [UX-01](UX-01.md)

As an editor, I want each state and action to have a clear, consistent meaning, so I know what happened and what to do next.

## Current evidence

StatusBadge, StatusPill, source states, and Instagram states use different treatments. Some errors use hint styling. Labels still include 'Topics disponibles', 'Carrousel', generic 'Approve', 'Saved studies', and technical terms such as 'Saved in Neon'.

**Surfaces:** [radar-dashboard.tsx](../../src/app/radar-dashboard.tsx) · [creative-draft-workspace.tsx](../../src/app/creative-draft-workspace.tsx) · [topic-configuration-panel.tsx](../../src/app/topic-configuration-panel.tsx) · [daily-preparation-panel.tsx](../../src/app/daily-preparation-panel.tsx) · [daily-preparation.types.ts](../../src/app/modules/stories/daily-preparation.types.ts) · [meta-connection-panel.tsx](../../src/app/meta-connection-panel.tsx).

## Acceptance criteria

1. Define shared presentation for loading, first-use empty, filtered-empty, recoverable error, blocked, stale, read-only, unsaved, saving, saved, and running. Keep domain status values intact.
2. Distinguish Story approval, script approval, image approval, and authorization to publish in labels and feedback. Automated review is never labeled as human approval.
3. Use English across visible copy, ARIA text, tooltips, confirmations, counts, and date formatting. Correct remaining mixed-language labels and standardize 'carousel', 'Story', 'Script', 'Visuals', and 'Publication'. Preserve authored content.
4. Place errors near the failed operation and provide a relevant recovery action. Success feedback states what was saved or created; loading and polling do not repeatedly announce the entire panel.
5. Every blocked primary action has a persistent reason and a link or action to resolve it. Do not rely on a title tooltip over a disabled button.
6. Move model, database, hash, and run diagnostics behind a labeled disclosure when they do not help the current decision. Show timestamps with explicit zone where operationally relevant.

## Validation

Audit copy in each inventory row, including screen-reader labels. Check offline, stale, empty, saving, and publication-uncertain fixtures; verify that notices neither disappear before reading nor repeat excessively.

## Scope and delivery

A common badge does not collapse distinct domain states or hide factual, permission, or publication blockers.

## Implementation progress — September 27, 2026

- Daily preparation labels now use Script, Carousel, and Visuals, and preferences report a user-facing saved state rather than database implementation detail.
- Dashboard operation errors and Overview load failures now announce as alerts; successful status messages remain polite updates.
