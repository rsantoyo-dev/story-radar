# UX-13 — Make source discovery and Story creation simple and consistent

**Status:** In progress · **Priority:** P1  
**Feature:** [Consistent interface and editorial experience](../features/ui-ux-consistency.md)  
**Dependencies:** [UX-01](UX-01.md), [UX-02](UX-02.md), [UX-03](UX-03.md), [UX-04](UX-04.md), [UX-05](UX-05.md)

As an editor, I want to add material or write a Story with a clear result and scope, so I can get it into the editorial workflow quickly.

## Current evidence

Source tabs show shared catalogs and Topic settings in long combined views. Add source has a useful detect/confirm flow, while New story starts with campaign/en/global and labels its material date 'Publish date'.

**Surfaces:** [add-source-dialog.tsx](../../src/app/add-source-dialog.tsx) · [new-story-dialog.tsx](../../src/app/new-story-dialog.tsx) · [topic-configuration-panel.tsx](../../src/app/topic-configuration-panel.tsx).

## Acceptance criteria

1. Use the same list anatomy for RSS, AI research, and original content: identity, type, linked Topics, active/health state, last useful activity, and contextual actions.
2. Make current-Topic versus workspace catalog scope visible. Differentiate Link, Unlink, Disable, and Delete; show affected Topics when changing shared settings.
3. Retain Add source's detection preview and confirmation. Show selected Topics, detected kind, and the resulting feed, document, or Story; invalid input retains the user's draft.
4. Guard file-drop changes while a request is active, keep preview tied to its exact input, and make file selection keyboard accessible.
5. Give New story a concise required path for Topic, title, and content. Use available Topic defaults for content language and region; keep optional provenance and material date in a clear details section.
6. Label the material date according to its actual meaning and explicitly distinguish it from social scheduling. Preserve the existing content-type compatibility contract until the owning domain story broadens it.
7. After success, link to the created resource and the next editorial action. Creating source material never presents itself as publication.

## Validation

Exercise existing-feed reuse, multi-Topic linking, invalid URL/PDF, interrupted detection, attempted file change while busy, manual content without URL, and a non-English Topic default.

## Scope and delivery

Reuse SRC-01–08. UI improvements do not introduce a separate manual-Story pipeline or expand content enums without domain work.

## Implementation progress — September 28, 2026

- New Story now prioritizes Topic, title, and content; content type, language, region, material date, and optional URL sit in a details section. It uses the current Topic’s loaded creative-profile language/region when available and explicitly says the material date does not schedule publication.
- Add Source now ignores file drops while a request is active. Both creation dialogs use the shared modal focus behavior and confirm before discarding entered data.
- Remaining: cross-Topic defaults, catalog list anatomy, existing-source reuse, and full detection/creation browser fixtures.
