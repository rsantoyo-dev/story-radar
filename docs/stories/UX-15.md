# UX-15 — Bring content, evidence, and focus into the Story workspace

**Status:** In progress · **Priority:** P0  
**Feature:** [Consistent interface and editorial experience](../features/ui-ux-consistency.md)  
**Dependencies:** [UX-01](UX-01.md), [UX-02](UX-02.md), [UX-03](UX-03.md), [UX-04](UX-04.md), [UX-05](UX-05.md)

As an editor, I want to review evidence, improve content, and set the focus in one workspace, so the script starts from material I understand.

## Current evidence

The Content stage offers a button that opens StoryContentViewer. Saving content asks the user to refresh the studio manually. Brief facts, risks, and angle are available but presented separately from the source editing task.

**Surfaces:** [radar-dashboard.tsx](../../src/app/radar-dashboard.tsx) · [creative-draft-workspace.tsx](../../src/app/creative-draft-workspace.tsx) · [story-photos-panel.tsx](../../src/app/story-photos-panel.tsx) · [story-workspace-page-client.tsx](../../src/app/topics/[topicId]/stories/[storyId]/story-workspace-page-client.tsx).

## Acceptance criteria

1. Render the content review/editor directly in the Content stage where practical, using the shared editor/dialog contract for secondary details. Keep original source and editorial working copy distinguishable.
2. Keep title, readable content, revisions, source references, and evidence photos accessible without losing the current Story and Topic context.
3. After saving, show the new content revision and explicitly mark dependent brief/script state as current or requiring review. Offer the next action without silently regenerating or discarding unsaved script edits.
4. Structure Focus around audience, editorial intent, evidence-supported angle, hook, and unresolved risks. Put technical plan metadata behind details.
5. Separate blocking evidence gaps from advisories; offer supported enrichment, editing, and review actions while retaining the existing approval scope.
6. Keep content with no public URL usable and preserve all available provenance. Opening a past revision is read-only until the editor explicitly creates a working copy.

## Validation

Edit content, save, inspect the prior revision, and proceed to Focus. Exercise a missing article, document/manual Story, limited evidence, stale brief, and unsaved script during content refresh.

## Scope and delivery

Reuse current content revisions and brief contracts. Do not invent facts, resolve source conflicts silently, or create a new Story aggregate in a UI change.
