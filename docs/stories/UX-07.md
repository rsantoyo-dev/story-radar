# UX-07 — Simplify Discover, evaluation, and Story lists

**Status:** In progress · **Priority:** P0  
**Feature:** [Consistent interface and editorial experience](../features/ui-ux-consistency.md)  
**Dependencies:** [UX-01](UX-01.md), [UX-02](UX-02.md), [UX-04](UX-04.md), [UX-05](UX-05.md)

As an editor, I want to compare opportunities and select suitable Stories, so I can make an informed choice without decoding a dense operational table.

## Current evidence

EditorialEvaluationPanel exposes provider details and numbered legacy sections. StoryListControls shows many ranking and filtering controls; the same wide table is used across discovery and production. TableHeader lacks an explicit column scope.

**Surfaces:** [radar-dashboard.tsx](../../src/app/radar-dashboard.tsx) · [editorial-lines-panel.tsx](../../src/app/editorial-lines-panel.tsx).

## Acceptance criteria

1. Use a compact Discover header and visible editorial-line/research scope. Put advanced ranking and diagnostics in a disclosure; keep active filters and a clear Reset visible.
2. Use the same Story row/card anatomy: title, source/time context, separate editorial and growth signals, content state, selection state, and one relevant next action.
3. Make score meaning and missing/stale values explicit. Preserve signal explanations; do not display legacy zero as a completed weak score without state evidence.
4. Make bulk selection scope explicit, including selected rows hidden by filters. Preserve the existing distinction between shortlist eligibility, recommendation, editor selection, and persisted approval.
5. Give table headers and sorting controls correct semantics. Offer a compact mobile presentation or an intentionally scrollable comparison table with title/action context retained.
6. Provide specific empty, filtered-empty, partial-evaluation, duplicate, and failed-enrichment states, with an appropriate recovery action and preserved filters.

## Validation

Compare Stories with strong editorial/weak growth and the reverse. Exercise hidden selected rows, duplicate review, missing score, long titles, 200% zoom, and 100+ candidates without duplicating a review action.

## Scope and delivery

Reuse evaluation and source-identity logic; no new scores, automatic selection policy, or URL-only deduplication.

## Implementation progress — September 28, 2026

- Comparison table headers now declare column scope. Legacy zero scores render as unavailable rather than as completed weak scores.
- Discover now shows Collected, Evaluated, and Selected counts before the evaluation detail. Collected and Evaluated open the corresponding candidate scope; Selected opens the Production queue. The copy states that these counts overlap, and switching scope clears narrower saved filters.
- Remaining: simplify filters and mobile presentation, make bulk selection scope explicit, and validate empty/partial states with large fixtures.
