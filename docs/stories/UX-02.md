# UX-02 — Standardize forms, validation, and save boundaries

**Status:** In progress · **Priority:** P0  
**Feature:** [Consistent interface and editorial experience](../features/ui-ux-consistency.md)  
**Dependencies:** [UX-01](UX-01.md)

As an editor, I want to understand what is required, what is wrong, and what my Save action will persist, so I can configure the brand without losing edits.

## Current evidence

TextField, TextAreaField, ListField, Field, and NumberField are separate field contracts. ListField commits on blur. Profiles, references, and characters also save through different actions within one screen.

**Surfaces:** [creative-profile-fields.tsx](../../src/app/creative-profile-fields.tsx) · [editorial-profile-panel.tsx](../../src/app/editorial-profile-panel.tsx) · [topic-configuration-panel.tsx](../../src/app/topic-configuration-panel.tsx) · [editorial-lines-panel.tsx](../../src/app/editorial-lines-panel.tsx).

## Acceptance criteria

1. Adopt one visible label, hint, required/optional, error, and help association pattern. Use aria-invalid and aria-describedby when relevant; placeholders supplement labels.
2. Keep a visible save state and a Save/Cancel row for the current editing scope. Independently saved references, characters, or connections state their own save boundary.
3. Commit all pending field input when Save is activated, including list fields still focused. Preserve input after a failed request and explain conflicts without silently overwriting newer data.
4. Disable repeated submits for the same operation while preserving useful navigation and unrelated forms. Explain disabled Save when required information is missing.
5. Show validation next to the affected field and focus the first relevant error after a failed submission. Numeric controls preserve intermediate editing values and validate before persistence.
6. Use readable content-language, region, and time-zone choices with an explicit fallback for existing custom values. The interface language remains English.

## Validation

Edit a comma-separated list and activate Save without changing focus; confirm the last text is included. Exercise an invalid number, validation response, network failure, stale revision, and an independently saved asset.

## Scope and delivery

Retain existing API schemas and revision checks. Do not auto-create default editorial profiles or auto-save approvals.

## Implementation progress — September 27, 2026

- Creative Profile list values now reach the parent draft on every change, so Save includes the focused field. Creative and Editorial profiles have explicit Save/Cancel controls and retain edits after a failed request.
- Editorial numeric fields keep incomplete input visible, report range errors beside the control, and focus the first invalid field on Save. The shared FormField associates help and error text with its control.
- Remaining: apply the field contract across the other configuration editors, add readable language/region/time-zone choices, and validate conflict, network, and keyboard flows with safe fixtures and screenshots.

Apply the feature's [shared visual contract and definition of done](../features/ui-ux-consistency.md), including UXDSL, English UI copy, responsive/keyboard checks, and preservation of approvals and history. Record implementation and visual evidence before changing status. The [component audit](../ui-ux-component-audit.md) lists every affected consumer.
