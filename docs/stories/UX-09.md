# UX-09 — Guide Topic setup and make management easy to scan

**Status:** In progress · **Priority:** P1  
**Feature:** [Consistent interface and editorial experience](../features/ui-ux-consistency.md)  
**Dependencies:** [UX-01](UX-01.md), [UX-02](UX-02.md), [UX-04](UX-04.md), [UX-05](UX-05.md)

As an editor, I want to create a brand and understand its remaining setup, so I can start collecting and producing confidently.

## Current evidence

Topic cards use an initial, description, and linked-source count. A second Topic selector and forms follow the cards; linked resources sit in a disclosure. Setup progress is not a consolidated guide.

**Surfaces:** [topic-configuration-panel.tsx](../../src/app/topic-configuration-panel.tsx) · [topic-configuration-panel.module.uxdsl](../../src/app/topic-configuration-panel.module.uxdsl).

## Acceptance criteria

1. Give each Topic card a consistent identity, purpose, active state, and truthful setup summary. Use an existing brand asset only when available; otherwise use the initial fallback.
2. Offer a short resumable Identity → Strategy → Sources → Channels guide, with links to the owning screen rather than duplicated configuration fields.
3. Derive readiness from existing records without creating or changing an editorial profile during a read. Label optional setup and publishing-only requirements distinctly.
4. Keep the top Topic selector authoritative. Contextual choices inside management are explicit and do not silently change the Topic being edited.
5. Provide clear edit, archive/inactive, and restore behavior only where supported. A read-only or inactive Topic remains identifiable and does not look like a broken card.
6. Use common form and save patterns; handle a long Topic name, no description, no linked source, and first-use setup.

## Validation

Create a Topic with minimal data, leave, and resume setup. Verify that viewing its checklist makes no domain write and does not alter legacy evaluation behavior.

## Scope and delivery

Reuse SRC-07 and current Topic endpoints. A persisted logo or setup workflow is not added unless the existing model can support it safely.

## Implementation progress — September 28, 2026

- Topic management now uses the top Topic selector as the single dropdown and shows the selected Topic plainly. A read-only Identity → Strategy → Sources → Channels guide links to the owning sections; its source count comes from existing catalog records and shows a loading state.
- Remaining: truthful channel and strategy readiness, inactive Topic review, and first-use/long-name browser validation. The guide does not read or create an editorial profile.

Apply the feature's [shared visual contract and definition of done](../features/ui-ux-consistency.md), including UXDSL, English UI copy, responsive/keyboard checks, and preservation of approvals and history. Record implementation and visual evidence before changing status. The [component audit](../ui-ux-component-audit.md) lists every affected consumer.

## Implementation progress — October 7, 2026

- Signed in, a brand opens the studio only after a full-screen guided setup (`topic-setup-wizard.tsx`): Identity (creative profile tabs, logo required, explicit confirmation) → Sources (at least one feed, document or AI research) → Channels (Facebook Page, or Instagram directly) → Ready. Each step embeds the screen that owns the configuration and unlocks "Continue" only when its records show it is done; progress is resumable and read without writes (`topic-setup.ts`, `GET/POST /api/radar/topics/[topicId]/setup`).
- `topics.setup_identity_confirmed_at` and `setup_completed_at` (migration 0095) record the two explicit decisions; the default workspace's brands were marked complete when the guide shipped. The story studio redirects an unfinished brand to its setup. With sign-in off nothing changes.
- Remaining: AI research toggle inside the Sources step, browser validation of the Facebook connect round trip on the deployed URL, and inactive Topic review.
