# UX-21 — Make Help contextual and Administration unmistakable

**Status:** In progress · **Priority:** P1  
**Feature:** [Consistent interface and editorial experience](../features/ui-ux-consistency.md)  
**Dependencies:** [UX-01](UX-01.md), [UX-03](UX-03.md), [UX-04](UX-04.md), [UX-05](UX-05.md)

As an editor or administrator, I want useful guidance and clear operational scope, so I can resolve a problem without confusing routine editorial work with maintenance.

## Current evidence

Help is a static four-step page. Administration is primarily a broad Clear data surface. Diagnostics, provider details, and storage names also appear inside editorial controls and place-policy setup.

**Surfaces:** [page.tsx](../../src/app/help/page.tsx) · [radar-dashboard.tsx](../../src/app/radar-dashboard.tsx) · [google-maps-preview-panel.tsx](../../src/app/google-maps-preview-panel.tsx) · [editorial-profile-panel.tsx](../../src/app/editorial-profile-panel.tsx).

## Acceptance criteria

1. Give Help the same shell, Topic context, English terminology, and task-specific links. Include short guidance for first setup, finding a Story, approving a version, and recovering a publication.
2. Make empty-state and blocker help land on the relevant section and return to the originating task. Avoid implying unavailable Facebook or calendar capabilities.
3. Group collection diagnostics, provider/environment checks, and map composition tests under clearly labeled advanced/administrative contexts while retaining links from affected work.
4. Before a destructive administrative action, display the actual scope and affected resource classes from its current contract, with explicit confirmation. Do not imply Topic-only deletion if the backend clears a broader scope.
5. Use consistent danger action styling and completion/error feedback. Do not remove existing confirmation or access controls.
6. Integrate session/account guidance with AUTH work; do not present the collector secret as a finished end-user login experience.

## Validation

Reach help from a blocked publication and return. Verify non-admin UI cannot gain authority through a hidden control, inspect destructive scope with safe fixtures, and open diagnostics without triggering a paid operation.

## Scope and delivery

AUTH owns access changes. This story neither executes maintenance nor broadens deletion behavior; validation uses non-production data.

## Implementation progress — September 28, 2026

- Help now links to setup, Discover, Production, and publication recovery with the selected Topic context. Administration describes the actual Topic-scoped clear contract rather than claiming sources are deleted. Clear and clear/collect show a scope confirmation before the existing typed DELETE gate runs.
- Remaining: task-specific blocker return links, advanced diagnostic grouping, safe destructive-flow fixtures, and AUTH integration. No maintenance action was executed.
