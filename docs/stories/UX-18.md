# UX-18 — Make publication review, authorization, and recovery clear

**Status:** In progress · **Priority:** P0  
**Feature:** [Consistent interface and editorial experience](../features/ui-ux-consistency.md)  
**Dependencies:** [UX-01](UX-01.md), [UX-03](UX-03.md), [UX-04](UX-04.md), [UX-05](UX-05.md), [UX-16](UX-16.md), [UX-17](UX-17.md)

As an editor, I want to review the exact account, copy, and media before authorizing publication, so I know what will be sent and whether it succeeded.

## Current evidence

The current flow requires Validate publication candidate, Freeze publication package, and Publish now. Frozen packages prominently show hashes, sizes, transforms, and delivery links. Job states already distinguish uncertain delivery and local record recovery.

**Surfaces:** [instagram-publication-candidate-panel.tsx](../../src/app/instagram-publication-candidate-panel.tsx) · [instagram-publishing-access-panel.tsx](../../src/app/instagram-publishing-access-panel.tsx) · [creative-draft-workspace.tsx](../../src/app/creative-draft-workspace.tsx) · [radar-dashboard.tsx](../../src/app/radar-dashboard.tsx).

## Acceptance criteria

1. Present a clear Review publication → Publish now interaction while retaining candidate validation and immutable package preparation internally. Preparing a review does not authorize sending.
2. Use the exact package's ordered media and caption for final preview, with account identity, destination, version, and relevant time zone. An earlier script preview is visibly provisional.
3. Show blockers with a direct path to the responsible stage or Channels. Revalidate changes to destination, approvals, or package freshness before enabling publication.
4. Move hashes, transformation details, byte sizes, and delivery diagnostics to an expandable technical section. Do not describe internal 'consumed' as a user-facing completion state.
5. Keep explicit final authorization, disable duplicate submission, and show truthful progress. Preserve the same order/package on retry; unknown outcomes expose reconciliation or recovery rather than a new send.
6. On confirmed publication, show the persisted Story link, published state, exact version, and permalink when available. If saving the local record is pending, make that state distinct from an unconfirmed remote result.
7. Only show scheduling and Facebook actions after the respective PUB capabilities exist. A manual tracking mark cannot masquerade as a provider-confirmed publication.

## Validation

Use blocked approvals, disconnected account, stale package, successful send, double click, uncertain remote result, and remote-success/local-save-failure fixtures. Review must make no publishing call until explicit authorization.

## Scope and delivery

Coordinate with PUB-14 for the single preview implementation and reuse PUB-01–08 for validation, packaging, sending, linking, and recovery. PUB-05/09/10 retain ownership of scheduling and Meta.

## Implementation progress — September 28, 2026

- The prepared package review now displays the exact Instagram account, frozen caption, hashtags, ordered media, and script revision when available. Hashes, transforms, byte sizes, and delivery links are under Technical delivery details.
- Publishing requires a separate inline confirmation after review. A synchronous request lock prevents repeated client submits while the existing server idempotency remains authoritative. Expired reviews cannot start publication. Focused freeze/publish domain tests pass.
- Remaining: blocked-stage links, full preview and recovery fixtures, confirmed Story/version linkage, and PUB-14 coordination. No live publication was performed.
