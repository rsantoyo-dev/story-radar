# UX-22 — Validate the complete experience across components and devices

**Status:** In progress · **Priority:** P0  
**Feature:** [Consistent interface and editorial experience](../features/ui-ux-consistency.md)  
**Dependencies:** [UX-01](UX-01.md), [UX-02](UX-02.md), [UX-03](UX-03.md), [UX-04](UX-04.md), [UX-05](UX-05.md), [UX-06](UX-06.md), [UX-07](UX-07.md), [UX-08](UX-08.md), [UX-09](UX-09.md), [UX-10](UX-10.md), [UX-11](UX-11.md), [UX-12](UX-12.md), [UX-13](UX-13.md), [UX-14](UX-14.md), [UX-15](UX-15.md), [UX-16](UX-16.md), [UX-17](UX-17.md), [UX-18](UX-18.md), [UX-19](UX-19.md), [UX-20](UX-20.md), [UX-21](UX-21.md)

As a product owner, I want evidence that the full editorial journey is consistent and easy to use, so the redesign is complete in real work rather than only in isolated screenshots.

## Current evidence

Shared styling compilation and unit tests do not prove keyboard usability, actual contrast, responsive readability, or that an editor understands approval boundaries. The current audit is source-based.

**Surfaces:** [ui-ux-component-audit.md](../../docs/ui-ux-component-audit.md) · [ui-ux-consistency.md](../../docs/features/ui-ux-consistency.md) · [app](../../src/app) · [design](../../src/design).

## Acceptance criteria

1. Create a reusable, non-production fixture set for first use, many Stories, long multilingual content, missing evidence, stale versions, historical images, partial permissions, and uncertain publication. Inventory every migrated consumer.
2. Capture component variants and real screen states at 390, 768, 1024, and 1440 px, 200% zoom, reduced motion, and at least two materially different Topic palettes.
3. Measure text/control contrast and inspect computed UXDSL tokens. Check focus visibility, keyboard reachability, screen-reader labels, heading order, overlays, error announcements, and touch targets.
4. Run end-to-end tasks: create a Topic; add a source/manual Story; evaluate/select; edit content/focus; save/review script; edit/review images; inspect final preview; authorize a mocked publication; recover it and inspect history.
5. With at least three representative editors, observe whether they can identify the current Topic, next action, saved state, and approval scope without coaching. Record task success, time, errors, and specific confusion; targets are goals, not claimed results.
6. Release gates: no lost edits in supported navigation; no accidental generation or send; no ambiguous provider confirmation; no unreachable primary action; no page-level overflow; no unresolved high-severity keyboard or contrast issue. Every inventory row is migrated or has an explicit reason and owner.
7. Record evidence and remaining limitations in the board and stories. Run required build/lint plus affected interaction and domain checks; visual snapshots supplement behavior tests.

## Validation

Use an approved local/test environment and mock external sends by default. A live publishing check requires an explicitly authorized test destination and must identify the immutable package. No story is marked done on screenshots alone.

## Scope and delivery

This is a release gate, not permission to publish, change automation policy, or claim usability research that has not occurred.

## Implementation progress — September 28, 2026

- A development-only showcase now includes two Topic palettes, shared control states, and safe fixtures for first use, a busy queue, multilingual copy, evidence gaps, stale revisions, historical images, partial permissions, and uncertain publication. No fixture can call a provider or send a post.
- A focused dialog interaction test covers initial focus, Tab containment, Escape, inert background, and focus return. The isolated localhost browser check also verified hydration, palette inheritance, focus, and no horizontal overflow at 390 px.
- Remaining: real authenticated screen captures at every target width and zoom, a complete keyboard and contrast audit, end-to-end tasks with mocked sends, and observation with three representative editors. These have not been claimed as passed.

Apply the feature's [shared visual contract and definition of done](../features/ui-ux-consistency.md), including UXDSL, English UI copy, responsive/keyboard checks, and preservation of approvals and history.
