# UXDSL findings log

What aligning Press Craftor with UXDSL teaches about UXDSL itself (see
[UXDSL alignment](features/uxdsl-alignment.md)). Newest first. Types: **bug**,
**gap**, **friction**, **advantage**. Each entry is meant to be filed or
quoted upstream as written.

| # | Date | Version | Type | Finding | Evidence | Workaround / status |
|---|---|---|---|---|---|---|
| 16 | 2026-10-08 | 0.5.0-beta.8 | bug | Composite tokens ignore a palette overridden on a container. Border, Shadow, Surface, Button and Input variables are declared on `:root` as `var(--uxdsl__palette__…)`, which resolves once against the root palette; an element that sets its own `--uxdsl__palette__*` (one theme per topic, several on one page) keeps the root colors in every role and preset, while direct `palette()` uses follow it. The plugin always emits the theme under `:root`; the generators take a selector the plugin does not expose. | After the migration, Studio borders and the back button showed the stock violet primary instead of the topic's palette. | The project's PostCSS step re-declares the palette-dependent composites under `[style*="--uxdsl__palette__"]`, the elements that carry a topic palette. Candidate upstream: emit composites for a configurable scope selector, or reference the palette lazily. |
| 15 | 2026-10-08 | 0.5.0-beta.8 | advantage | A whole app moved from literals to roles and tokens mechanically. | Two PostCSS codemods turned ~1,400 literal colors, sizes, radii, edges, shadows and type settings into 45 type roles, 40 border and 11 shadow presets, 8 Surface, 19 Button and 1 Input role (912 directives); the compiled CSS stays custom properties. | — |
| 14 | 2026-10-08 | 0.5.0-beta.8 | gap | No focus primitive for elements outside Button and Input roles. | 66 hand-written focus rules, 43 identical. | One `:where(a, button, summary, select, textarea, input, [tabindex]):focus-visible` rule in the theme entry built from `border(focus)` and `space(1)`; 45 copies removed. Candidate upstream: a focus token or directive. |
| 13 | 2026-10-08 | 0.5.0-beta.8 | gap | A weight change inside surrounding text cannot come from the type scale. Every `@ds-typo` role emits size, leading, family, tracking and margins; `inherit` values inherit from the parent element, not from another rule styling the same element. | Migration: a `textarea` whose size came from the shared field rule grew to its parent's size under an `inherit`-sized role; 5 such rules found and fixed. | `emphasis`/`regular` roles with `inherit` fields where the size comes from the parent; the strong variant of the sizing role where it comes from another rule. Candidate upstream: weight-only roles or a role that emits only its own fields. |
| 12 | 2026-10-08 | 0.5.0-beta.8 | friction | `@ds-input` emits `width: 100%`, `font: inherit` and an `:invalid` border; native `:invalid` matches an empty required field before the reader types. | Probe of a custom Input role's output. | The project's `field` role sets its invalid state to the resting edge. |
| 11 | 2026-10-08 | 0.5.0-beta.8 | friction | A custom Button role inherits the stock `hover` and `selected` states (a dark tone fill), even when its own base is a quiet text or outline style. | Probe: a role defining only `hover.border` rendered a dark hover fill; `aria-selected="true"` tabs would turn dark. | Every project role restates `hover` and `selected` (bg, color, border) through one helper in `uxdsl.config.js`. |
| 10 | 2026-10-08 | 0.5.0-beta.8 | bug | `border(n, color, style)` silently ignores its color and style when preset `n` exists; nothing warns. | 37 edges asked for primary, surface-dark, error or info colors and all rendered `--uxdsl__border__1` (gray-300); e.g. `.runPublishConfirm` compiles to `border: var(--uxdsl__border__1)`. | Migration keeps what actually rendered (`border(1)`/`border(2)`) so the look does not shift; the intended colors are a design decision to revisit. Ask upstream for a warning or an error. |
| 9 | 2026-10-08 | 0.5.0-beta.8 | friction | Finding 1 at scale: 137 rules write a block margin before `@ds-typo`, so the role's `margin-block: 0` silently cancels it. | Count after migration. | Kept the directive's position so spacing did not change; follow-up UXA-10 decides per rule whether the written margin was meant. |
| 8 | 2026-10-08 | 0.5.0-beta.8 | advantage | Upgrading beta.6 → beta.8 changed no component CSS. | All five generated CSS Modules compiled byte-identical with beta.6 and beta.8 from the same sources; `uxdsl.css` differed only in the position of an author comment (MIG-B7-14) and blank lines. | — |
